# Архитектура (черновик)

Основа: форк [keyboard-ds5](https://github.com/tejasbnshetty/keyboard-ds5). Связь с PS5,
привязку, окно настроек и раскладки берём из него. Меняем и добавляем то, что
описано ниже.

```
            ┌───────────────── RplayPS ─────────────────┐
Мышь ──Raw Input 1000 Гц──► [Скорость] ─► [Профиль] ─► [Кривая/LUT] ─┐
Клава ─LL-хук (перехват)──► [Раскладка] ─► кнопки, левый стик ────────┤
                                                                        ▼
                                              PadSender (≤125 Гц) ─► Remote Play ─► PS5
```

## 1. Ввод: напрямую из Windows, а не из окна браузера
Сейчас в keyboard-ds5 мышь читает веб-страница (pointer lock), это примерно 60 событий в
секунду. Мы будем читать её сами:

- **Мышь:** Raw Input (`RegisterRawInputDevices`, сообщения `WM_INPUT`) в отдельном потоке.
  Это скрытое окно, которое получает только сообщения. Так берём «сырые» отсчёты сенсора
  с частотой опроса мыши (500–1000 Гц), без ускорения Windows.
- **Клавиатура и кнопки мыши:** low-level хуки (`WH_KEYBOARD_LL`, `WH_MOUSE_LL`). В режиме
  захвата они **съедают** нажатия, чтобы те не попадали в другие окна.
- **Курсор:** `ClipCursor` + скрытие, чтобы он никуда не уезжал.
- **Включение и выключение захвата:** одна клавиша (F8 или F1, как в оригинале). Всё
  отпускается и центрируется, если захват снят, окно потеряло фокус или программа упала.
- Реализация: `ctypes` (pywin32 не нужен). Окно WebView остаётся только для настроек.

## 2. Мышь → стик: как в XIM
### 2.1 Скорость
- Отсчёты копятся с отметкой времени. Скорость считается по короткому окну (4–8 мс вместо
  нынешних 20–35 мс) или экспоненциальным сглаживанием.
- Сглаживание настраивается: меньше значит быстрее отклик, больше значит плавнее камера.

### 2.2 Кривая через таблицу (LUT) вместо формулы
Игра поворачивает камеру нелинейно относительно наклона стика: есть мёртвая зона, кривая
отклика и ускорение. Чтобы мышь ощущалась «как на ПК», нужна **обратная** кривая:

```
желаемая скорость поворота = чувствительность × скорость мыши
наклон стика = LUT⁻¹(желаемая скорость поворота)
```

- LUT хранит пары «наклон стика → скорость поворота камеры (°/с)». Её получаем калибровкой
  (2.3). Между точками используем линейную интерполяцию.
- Мёртвая зона учитывается автоматически: первая точка LUT — это наклон, при котором камера
  только начинает двигаться.
- Выход за верх LUT (мышь быстрее максимума игры) ограничиваем полным наклоном. Можно
  добавить «перенос остатка» на следующие тики, но только как опцию.
- Диагонали: проверить, круглая у игры мёртвая зона или по осям. От этого зависит, применять
  LUT к длине вектора или к каждой оси отдельно.

### 2.3 Мастер калибровки
1. Программа держит правый стик на фиксированном наклоне (например 0.15, 0.2 … 1.0).
2. Пользователь отмечает клавишей момент, когда камера совершила полный оборот: ориентир
   снова в центре экрана.
3. Из этого получаем °/с для каждого наклона и порог мёртвой зоны (наименьший наклон, при
   котором камера двигается).
4. Отдельные LUT для обычного режима, прицела и машины: игра крутит камеру в них по-разному.
5. Результат сохраняем как пресет `gta6.json`, которым можно поделиться.

## 3. Профили и режимы
| Режим | Как включается | Что меняется |
|---|---|---|
| Пешком | по умолчанию | LUT «пешком», обычная чувствительность |
| Прицел | автоматически, пока зажата ПКМ (L2) | LUT «прицел» и множитель чувствительности |
| Машина | клавишей (или по входу в машину, если удастся определить) | LUT «машина», A/D рулят левым стиком плавно |
| Колесо оружия/радио | пока зажат Tab (L1) | мышь задаёт **направление** стика (по накопленному смещению), а не скорость |

## 4. Клавиатура
- WASD → левый стик (уже есть). Модификатор «шаг» (уже есть).
- **Плавный руль:** при нажатии A/D в режиме машины стик наклоняется постепенно, а не
  сразу на 100 %.
- Кнопки мыши и колёсико назначаются (уже есть).
- Возможно: удержание Shift = частые нажатия «бега», если в GTA 6 бег по-прежнему
  требует постукивания. Только для одиночной игры.

## 5. Вывод на PS5
- `PadSender` из keyboard-ds5: события кнопок и состояние стиков. Состояние отправляется
  не чаще 125 раз в секунду (ограничение протокола в оригинале: 8 мс).
- Цикл вывода: 125 Гц. Ввод при этом читается на 1000 Гц, так что каждый тик берёт свежие данные.

## 6. Тесты без PS5
- Модульные тесты для расчёта скорости, LUT, интерполяции и профилей (в оригинале уже есть pytest).
- **Режим «без консоли»:** весь путь от мыши до стика с визуализатором стика на экране,
  но без отправки на PS5. Кривую можно отлаживать без консоли.
